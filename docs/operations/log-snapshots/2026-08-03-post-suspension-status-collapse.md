## 何が起きたか

7/26〜7/31 の配信停止（`pushSuspension.ts`）で**こちらが問題を送っていなかった**ため、
ユーザーは解きようがなかった。それなのに `lastAnsweredAt` だけが古くなり、
`recalculateUserStatuses` が大量のユーザーを dormant / churned に落とした。
dailyQuiz は `status === 'active'` にしか配信しないため、8/1 に配信が自動再開しても
**大半のユーザーには何も届いていなかった**。

ユーザーからの指摘「朝設定なのに今日の分が送られてこない」で発覚。

## 復旧

`userStatus.effectiveLastAnsweredAt()` を追加し、**停止の30日前〜停止開始（6/26〜7/26）に
回答があった人**だけ判定の起点を再開日（8/3）へ繰り上げるようにした（詳細は
`docs/operations/line-message-system.md` §2.8）。

`scripts/restore-status-after-suspension.ts --apply` で即時反映:

| 変更前 status | 件数 |
|---|---:|
| dormant | 994 |
| churned | 716 |
| **合計** | **1,710** |

候補 1,880件のうち、ブロック中・配信おやすみ中の 167件はスキップ（本人の選択を尊重）。
復旧後の active は概算 **1,152 + 1,710 = 約 2,862人**。

## 教訓（次に配信を止めるとき）

**push を止めると、止めた期間ぶんだけユーザーが「勝手に休眠」する。**
`status` は「ユーザーが解かなくなった」ではなく「解く機会がなかった」も同じ値になる。
配信停止を入れるときは、**同時に status 判定側にも停止期間の除外を入れる**こと。
そうしないと再開しても配信が戻らず、しかも「壊れている」と受け取られる。
