> ⚠️ **`_sample-question-impact2.mjs` の結果は誤りなので使わないこと。**
> `users.lastAnsweredAt`（＝**最後**の回答日）で「登録7日以内に解いたか」を判定していたため、
> 実際に数えていたのは「登録7日以内に解いて**その後やめた人**」だけで、継続中の人が全部こぼれていた。
> しかも導入後コホートのほうが若い（＝最後の回答が登録の近くに寄る）ぶん有利に出るため、
> 「25.9% → 37.0%（+11pt）」という**存在しない改善**が見えていた。
> 正しくは `answers` から初回回答を取る（既存 index は `answers(uid ASC, answeredAt DESC)` のみなので、
> asc の orderBy は使えない。「登録+N日以内の回答が1件でも存在するか」を DESC＋範囲で判定する）。

## 何を測ったか

友だち追加直後の reply に静的1問を同梱する「おためし1問」（`line-message-system.md` §2.52・
`.steering/20260703-line-sample-question-streak-forgiveness/`）を **2026-07-03 に導入**した。
当初の狙いは「登録48h以内のブロック（全ブロックの46%）を減らすこと」。

## 利用実績

| 項目 | 値 |
|---|---|
| `sample_question_answered` 総数 | **775件**（7月 734 / 8月 41） |
| 初回イベント | 2026-07-03 |
| 正答率 | 77% |
| 7月新規1,745人に対するタップ率 | 約42% |

## 導入前後の比較（登録コホート・初回回答は answers から取得）

導入後は全員が登録から7日以上経った 7/06〜7/27 に限定（経過日数をそろえる）。

| 指標 | 導入前 6/03-7/02（1,581人） | 導入後 7/06-7/27（1,271人） | 差 |
|---|---:|---:|---|
| 一度でも解いた | 93.4% (1,477) | 92.1% (1,171) | −1.3pt |
| **登録24時間以内に初回回答** | 82.3% (1,301) | **85.5% (1,087)** | **+3.2pt** |
| 登録48時間以内に初回回答 | 87.6% (1,385) | 89.2% (1,134) | +1.6pt |
| 登録7日以内に初回回答 | 91.5% (1,447) | 91.2% (1,159) | −0.3pt |
| 一度も解いていない | 6.6% (104) | 7.9% (100) | +1.3pt |
| 登録7日以内にブロック | 6.6% (104) | 6.2% (79) | −0.4pt |

## 結論

- **当初の狙い（ブロック抑止）は効いていない**（登録7日以内ブロック 6.6% → 6.2%）。
- **7日以内の学習着手率も動いていない**（91.5% → 91.2%）。**もともと9割が最初の週に解いており、
  ここに伸びしろが無かった**。
- 唯一動いたのは**初日の立ち上がり**（24時間以内 82.3% → 85.5%・+3.2pt）。
  「登録した日のうちに1問解く」人が3ポイント増えた、という程度の効果。
- 交絡: 7月は範囲設定のトーク内フロー化なども走っており、7/26〜7/31 は配信停止。
  差が小さいので、**この程度の差を効果と断定しないほうがよい**。

## 教訓（測定側）

**「◯日以内に解いたか」を `users.lastAnsweredAt` で測ってはいけない。**
`lastAnsweredAt` は最後の回答日なので、継続しているユーザーほど条件から外れ、
「早く始めて早くやめた人」だけを数えることになる。初回接触を測るなら `answers` を見る。
