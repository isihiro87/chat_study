# 公式LINE Bot は2つある — 「チャットでスタディ」と「つづもん」の違い（正本）

> 作成: 2026-07-25 / 対象: Claude Code・Codex・開発者
> このリポジトリは **2つの LINE 公式アカウント**を運用する。片方の前提でコードを書くと事故るため、
> 着手前にこの表を読むこと。実装状況は「状態」列で必ず確認する（**未実装のものを実装済みと誤認しないこと**）。

## 0. いちばん重要な3点

1. **replyToken はチャネル固有**。チャネルAの webhook が受け取った replyToken を、チャネルBのアクセストークンで使うと `400 Invalid reply token` になる。**Bot をまたいでクライアントを共有できない。**
2. **`users/{uid}` は両Botで共有**（同一プロバイダーなので `uid = line:{userId}` が一致）。だから「一問一答で解いた記録」をつづもんのAIが見られる。これは**意図した挙動**。
3. **一問一答Bot（3,000フォロワー・稼働中）のロジック・分岐・文言は無改修が原則**。つづもん側の都合で触らない。

## 3. AI（一問一答＝スタ先生／つづもん＝つづ先生）の違い ← ここが最大の差

**AIペルソナの名前はBot別**（2026-07-26 に分離）。一問一答・ムビスタは「スタ先生」、つづもんは
「つづ先生」（参考書Web内チャット・参考書QR対話も含む）。プロンプト・UI文言を書くときに取り違えないこと。
中身（内部の能力・コスト）も次のとおり違う。

| | 一問一答（`free` ティア） | つづもん（`paid` ティア） |
|---|---|---|
| 状態 | ✅ **稼働中** | ✅ **稼働中**（2026-07-25 デプロイ。フェーズ1〜6完了・7〜10は未実装） |
| API 予算 | 節約優先（**約 ¥0.36 / ターン**の実測ベース） | **課金1人あたり月300〜400円**（売上1,280円の23〜31%） |
| モデル | `gemini-3.1-flash-lite` 固定（`counsel` のみ `LLM_MODEL_FREE_COUNSEL` で1段上げられる・**既定は未設定**） | ✅ 用途別3階層（`classify`/`chat`/`analysis`/`plan`/`counsel`/`verify`） |
| 上限の測り方 | **1日40回**（回数制） | ✅ **月次コスト予算制**（円換算・5層キャップ・段階デグレード） |

| ツール実行 | なし（返信のみ・「実行したフリ禁止」） | 🚧 未実装（フェーズ8） |

> 触れることはない。3日間無料お試し（`tsudumon.source==='trial'`）は `paid` だが予算は 1/7。

### 3-1. プロンプトの決定的な違い（文言衝突）

現行プロンプト（`aiChatPrompt.ts` の `SERVICE_KNOWLEDGE`）は次を**断言する**。

- 「この公式LINEの機能はすべて**無料**」
- 「有料プラン・月額料金・トライアル・申し込みは**今はない**」

→ **つづもんBotでこれをそのまま使うと自己矛盾する**（月額1,280円のサブスクだから）。つづもん用は「月額1,280円のつづもん（参考書19冊＋問題集＋AI採点）の先生」として振る舞うプロンプト分岐が必要。

なお `PREMIUM_FLOW_ENABLED=false`（公式LINEのプレミアムは休眠中）は据え置き。**課金はつづもんのサブスクのみ**で、公式LINEのプレミアム復活とは無関係。

### 3-2. 現状の共有点（将来分離予定）

- 1日40回枠（`users/{uid}.aiChat.count`）は**両Bot共通**。`tsudumon-dedicated-line-bot/design.md` では「コスト上限の一元管理＝意図した挙動」とされている。
- 参考書AI対話・ワーク採点・記述採点も**この同じ40回枠を消費**する。
- → AI 個別サポート実装時に `paid` を予算制へ分離する（`ai-personal-support/requirements.md` §機能3）。

### 3-3. `free` 側の改修（2026-07-26・`.steering/20260726-free-ai-chat-improvement/`）

無料側は「削って・測って・その範囲で買う」方針で見直した。**1ターンあたり ¥0.41 → 約 ¥0.36**。

| やったこと | 効果 |
|---|---|
| 決定論の安全分類を `free` にも（`aiCrisisHandler`） | `crisis` は AI を呼ばず固定文＋通知。**コストはむしろ下がる** |
| プロバイダ停止の運営通知を `free` にも（`aiProviderAlert`） | 3,000人の AI が黙っていることに運営が気づける |
| `llmProvider` 経由へ移行 | 実トークン・キャッシュヒット率・円換算が取れ、**全体キャップ②層に載る** |
| プロンプトを話題別ブロックへ分割 | 入力を**平均31%削減**（`ICHIMON_OPTIONAL_BLOCKS`） |
| Quick Reply の拡充・上限到達時の出口 | 取りこぼしを回収。**配信枠もコストも増えない** |
| 履歴 6→10ターン / 出力 500→700 / 途中切れの始末 | 上の削減で相殺できる範囲で体験を買う |
| 軽量プロフィール記憶（`aiFreeProfile`） | 20ターンに1回だけ抽出。1ターンあたり約 ¥0.004 |

**`free` に入れなかったもの**: Web検索・全会話アーカイブ・ツール実行・教材接地フル版
（3,000人規模では read とコストが見合わない）。

## 4. 状態フィールドの分離（混ぜると事故る）

| 用途 | 一問一答 | つづもん |
|---|---|---|
| ブロック状態 | `blocked` / `blockedAt` / `unblockedAt`（**15ファイル・62箇所**で配信除外判定に使用） | `tsudumonFollowed` / `tsudumonFollowedAt` / `tsudumonBlockedAt` |
| オンボーディング | `onboardingState` | **書かない**（既存ユーザーのオンボ状態を壊すため `handleFollow` は流用禁止） |
| 有料判定 | `plan` / `premiumUntil`（**休眠中**） | `tsudumon`（code / plan / years / activatedAt / expiresAt）→ `evaluateTsudumonAccess` で**追加read ゼロ**で判定 |
| 回答の由来 | `answers.source`（通常） | `answers.source === 'workbook'` → `onAnswerCreated` が返信先Botを振り分ける |

**つづもんをブロックしても一問一答の毎日配信は止まらない／その逆も同じ** — これが分離の受け入れ条件。

## 7. 実装時の落とし穴（実際に踏んだ／踏みかけたもの）

| 落とし穴 | 対策 |
|---|---|
| **replyToken をBotまたぎで使う** → `400 Invalid reply token` | つづもん系ハンドラは `client` を引数で受ける。既存呼び出し元は `await getLineClient()` を渡す＝旧Botの挙動は不変 |
| `getTsudumonLineClient()` が旧トークンにフォールバック | **してはならない**。3,000人へ誤送信する |
| `handleFollow` を新Botで流用 | `onboardingState:'started'` / `blocked:false` を無条件に書くため、**既存ユーザーのオンボ状態が壊れる**。専用の `handleTsudumonFollow` を使う |
| つづもん配信除外に `blocked` を使う | 一問一答のブロック状態で除外されてしまう。`tsudumonBlockedAt` を見る |
| つづもんユーザーに一問一答のナッジが届く | `onAnswerCreated` で `source === 'workbook'` のとき範囲設定ナッジ・Win-back系を送らない |
| つづもんBotで「全機能無料」と言う | プロンプトをBot別に分岐する（§3-1） |
| `getLineClient()` を全面channel引数化しようとする | 17ファイル・106箇所。一問一答の全経路に手が入り回帰リスクが高い。**つづもん系だけ引数化**する |
| Functions 全体デプロイ | discovery timeout ＋ Instagram シークレット未設定で失敗する。**対象を絞ってデプロイ**（CLAUDE.md 参照） |

## 8. 判断に迷ったときの原則

1. **一問一答（3,000人・無料）を壊さないことが最優先。** つづもんの都合で既存ロジック・文言・分岐を変えない。
2. **無料側は節約、つづもん側は品質。** read 規律・モデル・履歴の方針を混ぜない。`free` の挙動は現状維持が受け入れ条件。
3. **Bot固有の状態はBot別フィールドへ。** 共有フィールド（`blocked` / `onboardingState`）に書かない。
4. **push は必ず「どちらのBotか」を決めてから送る。**
5. **公式LINEの単元は `data/content/` が正**（`eras` / `topic-registry` は Web版専用・混同禁止＝CLAUDE.md 冒頭）。
